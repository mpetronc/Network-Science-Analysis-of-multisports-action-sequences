# Network-Science-Analysis-of-multisports-action-sequences

This project is a robust Python analytics pipeline for the 2025–26 NBA regular season designed to map, analyze, and visualize how basketball teams move the ball.It bridges sports analytics, graph theory, and information theory to evaluate team passing dynamics. Here is a breakdown of what the project does in its current form:
1. Automated Data Acquisition & CachingFull Roster Coverage: Queries the official nba_api tracking endpoints (LeagueDashPlayerStats and PlayerDashPtPass) to pull passing profiles for all active players across teams, automatically filtering out players with zero minutes.   Local Disk Caching: Saves raw player data into a safe home directory (~/nba_passing_cache) so that subsequent runs load instantly without re-downloading or triggering server limits.
2. Anti-Blocking & Error ResilienceBrowser Mimicking & Jitter: Uses realistic user-agent headers and randomized delays between requests to prevent Cloudflare and NBA.com firewalls from blocking or throttling the script.Socket Flushing & Retries: Equipped with exponential backoff and explicit TCP socket clearing (NBAStatsHTTP.clear_session()) to automatically recover from server read timeouts.
3. Graph Construction & Information-Centric MetricsDirected Adjacency Matrices: Compiles each team's passing data into a square weighted matrix ($A_{ij}$), where rows and columns represent players and cell values represent total passes completed from player $i$ to player $j$.Information Entropy Analysis:Receiver Entropy: Quantifies how evenly distributed incoming ball flow is across a team (distinguishing heliocentric offenses from egalitarian, ball-sharing systems).Conditional Entropy (Entropy Rate): Measures the predictability or multi-dimensionality of a player's outgoing passing choices.
4. Network VisualizationNetworkX & Matplotlib Integration: Converts the adjacency matrices into directed network graphs.Visual Encoding: Automatically draws the team's passing web where node sizes scale with overall passing volume/involvement, and edge thickness reflects frequent passing combinations between specific teammates.

Configuration & Caching LayerDirectory Setup: Write code to check for and create a local cache folder (such as ~/nba_passing_cache) in your home directory to avoid write permission errors.Cache Management: Implement helper logic that checks if a player's passing data is already saved locally as a .pkl file. If it exists, load it instantly; otherwise, fetch it from the API and save it to disk.2. Data Ingestion & API HandlersLeague Roster Fetcher: Code that queries the league advanced stats endpoint (LeagueDashPlayerStats), applies browser-mimicking headers to prevent blocks, and filters out inactive players who have zero games or minutes played.Player Tracking Fetcher: Code that queries the individual tracking endpoint (PlayerDashPtPass), implements retry loops with exponential backoff, adds randomized time delays (jitter) between requests, and includes TCP socket clearing (NBAStatsHTTP.clear_session()) to recover from server timeouts.3. Graph Construction & Adjacency Matrix BuilderPlayer Index Mapping: Code that maps each active player's unique PLAYER_ID to a sequential row/column index (0 to n-1).Matrix Population: Code that initializes an $n \times n$ zero matrix using NumPy for each team, iterates through a player's completed passes (PASS_TEAMMATE_PLAYER_ID), and populates the exact pass counts into the corresponding matrix coordinates ($A_{ij}$).4. Information-Theoretic Metric CalculatorsReceiver Entropy Function: Code that calculates the probability distribution of incoming passes across all teammates ($p = \text{incoming} / \text{total}$), computes Shannon entropy, and normalizes it by $\log(n-1)$ to measure ball intake concentration.Conditional Entropy Function: Code that evaluates outgoing passing choices for each player, calculates their local entropy, and weighs it by their overall share of team passes to measure passing predictability.5. Network Visualization LayerGraph Transformation: Code that converts the NumPy adjacency matrix into a NetworkX directed graph (nx.DiGraph), mapping player IDs to short, readable names (initials and last name).Layout & Scaling Engine: Code that computes node positions via spring layout, scales node sizes based on total passing volume (in-degree + out-degree), and normalizes edge widths by pass frequency.Plot Renderer: Code that draws nodes, curved directed arrows to prevent mutual pass overlap (connectionstyle="arc3,rad=0.1"), labels, and renders the final figure using Matplotlib.
